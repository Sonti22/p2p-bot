# P2P-сканер + Telegram-бот

Ищет связки за рубли на P2P Bybit, HTX, KuCoin, MEXC, BitPapa, LBank и у обменников BestChange
по публичным эндпоинтам (без API-ключей). Монеты: USDT, USDC, BTC, ETH, TON (`ASSETS`; у LBank — только USDT и USDC).
Связки: та же монета между площадками и P2P↔спот через USDT (конвертация на споте Bybit, чего там нет — MEXC).
`/top` показывает и лучшие цены USDT у обменников по сетям (TRC20, BEP20, TON, SOL, ERC20…).
Считает чистый % на сумму круга с учётом комиссий перевода и спота, отсеивает слабых мерчантов,
неподходящие лимиты и аномальные цены (>±MAX_DEV% от ориентира: Rapira USDT/RUB × спот монеты).

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env        # вписать TG_TOKEN от @BotFather и свой Telegram user ID в TG_CHAT_ID
python p2p.py               # разовый срез в консоль
python bot.py               # бот (или run.bat); TG_CHAT_ID заранее задан на ПК, затем /start в личку
                            # (владелец — только личный чат: группа или канал владельцем не станут)
python scripts/merchant_suggest.py data/snapshots.db   # предложение MERCHANT_MIN по снимкам (только чтение базы)
```

## Команды бота

Подробно для владельца — команды, кнопки, метки, режимы `.env`, launcher и `--approve`: [docs/owner-guide.md](docs/owner-guide.md).

Рыночные (доступны и гостям из `TG_GUESTS`):
- `/top` — топ связок картинкой-графиком.
- `/best` — лучшая связка сейчас.
- `/calc 20000` — разовый расчёт под свою сумму круга (без смены настроек); принимает «20000», «20 000», «20к», «1,5 млн».
- `/maker USDT` — цена, чтобы встать первым объявлением на покупку/продажу, по каждой подключённой площадке;
  для лучшего варианта — место в стакане, 5 конкурентов рядом (лимиты, объём, сделки, оплата) и спред площадки.
- `/banks USDT` — сколько объявлений и объёма по каждому банку/способу оплаты, покупка и продажа.
- `/fees` — таблица комиссий вывода (`fees.json`) и возраст данных, рядом — живые комиссии бирж.
- `/history` — картинка «лучшее время суток» и хитмап спреда по часам/дням за 7 дней (кнопка «📉 Бэктест»).
- `/backtest` — бэктест связок по истории спредов: сколько раз были выше порога, оценка результата в ₽ (не прогноз).
- `/safety` — 115-ФЗ, блокировки карт, правила сделки (справка, не юридическая консультация).

Только для владельца:
- `/settings` — меню настроек (сумма, порог, площадки, монеты, тихие часы) кнопками, пишут в `.env`.
- `/amount 100000` — сумма круга. `/min 1.5` — порог сигнала, % чистыми.
- `/pause` (`30m`/`1h`/`3h`/«до утра») — пауза сигналов; `/resume` — снять.
- `/stats` — сводка по журналу сделок за день/неделю/месяц: число сделок, сумма, расчёт vs введённый факт; счётчик разных контрагентов по каждой своей карте за сегодня/месяц (ориентир ЦБ 16-МР, только информация). `/stats hours|dow|banks|coins` (и русские алиасы часы/дни/банки/монеты) — та же статистика по реальным сделкам за 90 дней, разбитая по часу (МСК), дню недели, банку оплаты или монете.
- `/nets` — сети площадок, которых бот не распознал: площадка, монета, имя, сколько раз и когда видели; на расчёт не влияет.
- `/export` (`month` / `year` / `prev`) — журнал сделок в CSV для банка и 3-НДФЛ.
- `/mybanks` — свои банки и бесплатные лимиты СБП.
- `/fav` — избранные маршруты.
- `/hedge` — хедж круга шортом перпа: открытые, закрыть; подробности — `docs/owner-guide.md`.
- `/filters` — монеты, площадки, банки, «только одна площадка».
- `/signals` — отчёт качества сигналов: доля пропущенных, причины, задержка, топ направлений.
- `/alert USDT sell 92 7d` — алерт на целевой курс (условия «vol», «reliable», «repeat» — см. подсказку без аргумента); `/alerts` — список активных с удалением.
- `/blacklist` — скрытые мерчанты/обменники («🚫 Скрыть мерчанта» под сигналом): id, сколько дней в списке, причина; снятие — кнопкой, сами записи не удаляются. `/blacklist note <id> <текст>` — записать причину.
- `/traps` — последние отсеянные «ловушки»: площадка, цена, почему отсеяна.
- `/calibration` (при `CALIBRATION=1`) — калибровка плана по сухому прогону и фактам сделок: поправка факт − план по
  классам связок, вероятность исполнения по корзинам, EV, запас на курс из данных против `RISK_BUFFER` и хеджа.
  `EV_RANK=1` — `/top`, `/best` и сигналы по убыванию EV, в карточке «EV x.xx% (p=…)».
- `/paper` — сухой прогон (виртуальные круги без денег): открытый круг и стадия, итоги за день/неделю/всё время,
  план vs факт, теоретическая прибыль в ₽ и % от оборота, виртуальный баланс, лимит СБП по банкам.
  `/paper on|off` — вкл/выкл, `/paper amount 20000` — сумма круга,
  `/paper reset` — обнулить с подтверждением (база уходит в архив). Только владельцу.
- `/paper report` — отчёт сухого прогона по площадкам и парам: круги, исполнилось/сорвалось и почему, средний план/факт,
  время стадий, нехватка глубины; следом — CSV-файл `data/paper_report.csv`.
  Там же — пороги бумажного хеджа и план хеджа реальных сделок по «✅ Сделал» (что открыл бы бот, без ордеров).
- `/funding` — бумажный арбитраж фандинга (`simfunding.py`, ордеров нет): перп–перп Bybit↔BingX и спот+шорт перпа Bybit,
  открытые позиции, начисленный фандинг, MTM, итоги и кандидаты с причиной отказа. Только владельцу.
- `/futures` — бумажная направленная стратегия на перпе Bybit (`simdirectional.py`: EMA 20/100 на 1ч свечах, стоп по ATR)
- `/shorts` — отдельные виртуальные шорты перегретых альтов Bybit: баланс, кандидаты, позиции, результаты, риск, CSV, pause/resume и research. Риск по стопу ≤0,5%, выделенный капитал ≤2% на позицию; без пополнения маржи. Методика и ограничения: [docs/ALT_SHORTS.md](docs/ALT_SHORTS.md).
  против случайных входов и «держать»: позиции, итоги, итог при комиссиях ×1. Только владельцу.
- `/maker paper` — отчёт бумажного мейкера (`simmaker.py`): свои виртуальные объявления по снимкам стакана, оценка
  исполнения (слабый прокси, так и помечен), круги и P&L. Только владельцу.
- `/balance` — баланс на подключённых биржах (`⚙️ Настройки → 🔑 Мои биржи`) картинкой-карточкой, итог в ₽.
- `/status` — версия, аптайм, время/длительность последнего скана, ошибки площадок (и таймауты `VENUE_TIMEOUT`:
  данные площадки в этом скане устарели), число связок выше порога; «⏱ Скорость» — p50/p90 длительности скана и
  задержки каждой площадки за последние 100 сканов, сколько раз она не успела.
- `/logs` — последние строки `logs/bot.log`.
- `/dev` — раздел разработки: ссылка на облачные запуски (`ROUTINE_URL`), статус, логи.
- `/allow <id>` / `/allow @ник` / `/deny <id>` / `/guests` — доступ гостям: сигналы и рыночные команды без настроек, ключей и журнала.

## Топики

Если у бота включён режим топиков в личке (@BotFather → настройки бота → режим топиков) — при первом
запуске бот заводит 4 темы и раскладывает сообщения: «🔔 Сигналы» (сигналы, алерты, ночной дайджест),
«📒 Журнал» (сделки, движения по аккаунтам), «⚙️ Настройки», «🛠 Разработка» (недоступность площадок,
статус). Id тем — в `data/topics.json`. Режим не включён — всё как раньше, одним чатом.

## Где держать

Круглосуточно — на VPS (1 vCPU / 512 MB хватит), как systemd-сервис или `docker run python:3.12-slim`.
Интервал не ниже ~10 с: чаще — бан по IP.

## Ограничения

- Сигнал = цена в стакане в момент скана. Перед сделкой открыть объявление и прочитать условия мерчанта.
- Эндпоинты неофициальные: биржа поменяет формат — адаптер в `p2p.py` придётся поправить.

## Интерфейс бота

- Сигналы приходят картинкой-карточкой: прибыль, купить → маршрут → продать, кнопки-ссылки на площадки и спот.
- Меню внизу: 🔥 лучшая связка сейчас, 📊 топ графиком, ⚙️ настройки (порог, сумма, пауза — кнопками, сохраняются в `.env`), ❓ как работать.
- Аватарки: `avatar_radar.png`, `avatar_neon.png`, `avatar_coins.png` (превью — `avatars_preview.png`, перерисовать: `python cards.py`). Поставить: @BotFather → `/setuserpic` → выбрать бота → отправить файл.

## Как устроена разработка

- План работ — `ROADMAP.md`. Облачный Claude (routine, 3 раза в день) берёт первую задачу, пишет код и тесты,
  пушит ветку `claude/...`.
- CI (`.github/workflows/ci.yml`): компиляция, `pytest`, `scripts/guard.py`. Для веток `claude/**` при зелёном
  результате PR мержится автоматически; иначе остаётся открытым для ручной проверки.
- `launcher.py` (через `run.bat`) на ПК каждые 5 минут проверяет `origin/main`, подтягивает обновление, прогоняет
  тесты, перезапускает бота и пишет в Telegram. Новая версия падает при старте — откат на последнюю рабочую.
- Локальные правки сначала закоммитить: при незакоммиченных изменениях launcher обновление не ставит.


### Виртуальный портфель на 50 000 ₽

При `PAPER_ENGINE=ledger` (по умолчанию) `/paper` показывает свободные рубли, резерв под покупки,
остатки монет и монеты в пути, прибыль исполненных продаж и оценку портфеля по свежей доступной
глубине продажи. Начальный капитал фиксирован: 50 000 ₽. `PAPER_AMOUNT` задаёт сумму одной операции;
`PAPER_MAX_OPEN` ограничивает одновременно открытые операции. Занятые деньги повторно не расходуются.
`PAPER=0` запрещает новые операции; уже открытые продолжают учитываться.

Покупка допускает частичное исполнение после задержки `PAPER_PAY_MINUTES`; через 30 минут
неиспользованный резерв возвращается. Маршрут, банковская/спотовая комиссия и задержки фиксируются
на старте; доступность перевода, минимальный объём и комиссия сети проверяются перед отправкой.
Переводы с неизвестным статусом сети не исполняются. При невозможности следующего шага в течение
30 минут симулятор пробует продать монеты на текущей площадке. Продажа сначала ждёт безубыточной
цены; после 30 минут допускает убыток. Недоступная глубина и минимумы объявлений сохраняют остаток,
а не списывают его. Каждый спотовый обмен исполняется отдельно и больше не пересчитывается задним числом.

`/paper report` и `/paper cycles` выгружают полный журнал CSV. Деньги хранятся Decimal-строками,
рублёвые оплаты округляются вверх до копейки, выручка вниз, количество монет вниз до 18 знаков.
Изменения портфеля и события записываются в одной SQLite-транзакции. Проверяется равенство:
свободные RUB + резерв + себестоимость остатков − реализованная прибыль = начальный капитал.
`portfolio.replay()` реконструирует состояния и свободные деньги из журнала.
`/paper reset` после подтверждения сохраняет отдельный SQLite-архив и создаёт новый портфель.
Автоматические резервные копии включают `paper_portfolio.db`. Прежний `paper.db` не изменяется
новым движком; `PAPER_ENGINE=legacy` позволяет отдельно просматривать прежнюю модель.

**Границы модели:** P2P-объявление не подтверждает согласие контрагента или реальную оплату;
используется опубликованный объём, лимиты и цена. Один полученный снимок объявления не используется
повторно сверх его объёма; новая выдача может показать тот же резерв снова. Спот по умолчанию (`PAPER_SPOT_MODEL=depth`) требует свежий стакан и правила пары.
Приближённый режим `ticker` явно помечает обмены `ticker_without_depth`. Сроки переводов
моделируются, а не подтверждаются блокчейном. Отсутствующая полная оценка показывается как неизвестная;
доходность портфеля и максимальная просадка считаются только по полным оценкам с указанием времени.
Хеджи и фандинг в новом портфеле исключены; старая лестница суммы по истории `paper.db` отключена.
Эти результаты не подтверждают исполнимость маршрута с реальными деньгами. Реальных ордеров,
оплат, выводов или запуска торгового ядра этот режим не выполняет.

Новый портфель работает только с `FIAT=RUB`. Объявления старше 120 секунд или без времени
получения не исполняются. Старые команды калибровки продолжают читать историю `paper.db`;
для анализа нового портфеля используются `/paper` и его CSV.


### Спот по глубине и остатки округления

Строгий банковский этап сохраняет текущий журнал и баланс, учитывает отдельные счета, общие лимиты,
входящие/исходящие операции и комиссии на фактическую сумму. Неподтверждённые профили и требования
P2P-объявления блокируют исполнение. `/paper banks` показывает причины. Подробности, структура
профилей и ограничения модели: [банковский учёт](docs/paper-bank-model.md).

Новый режим `depth` получает только публичные стаканы и параметры нужных активному маршруту пар
(Bybit, MEXC, HTX, KuCoin). Запросы ограничены общим сроком 5 секунд, включая очередь; отсутствующие,
устаревшие, перевёрнутые или некорректные данные не заменяются тикером. Стакан принимается не старше
15 секунд. Расчёт проходит по уровням bid/ask, проверяет доступный объём, шаг количества, точность
суммы и минимум/максимум операции. Используется консервативная модель: весь допустимый объём либо
ожидание; недостаточная глубина не считается полным исполнением. Объём уровня одного снимка не
используется повторно другими виртуальными кругами. Средняя цена, использованные уровни, правила
пары и полный исходный стакан сохраняются в журнале.

После округления оставшиеся монеты сохраняются отдельно на исходной площадке с долей себестоимости.
Они входят в проверку баланса, переоценку и восстановление из журнала, отображаются в `/paper` и могут
быть проданы при появлении допустимого P2P-объёма, даже после завершения основного круга. Они не
превращаются в свободные рубли до продажи. Комиссия спота пока берётся из настройки `SPOT_FEES` и
моделируется в получаемой монете; индивидуальные скидки аккаунта и альтернативная монета комиссии
не подтверждены. Стакан — снимок доступной ликвидности, а не подтверждение реального исполнения.
Исторические обмены по тикеру не переписываются.

Форматы публичных данных проверены по документации:
[Bybit: стакан](https://bybit-exchange.github.io/docs/v5/market/orderbook),
[Bybit: правила пары](https://bybit-exchange.github.io/docs/v5/market/instrument),
[MEXC](https://mexcdevelop.github.io/apidocs/spot_v3_en/#order-book),
[HTX](https://huobiapi.github.io/docs/spot/v1/en/#get-market-depth),
[KuCoin: стакан](https://www.kucoin.com/docs-new/rest/spot-trading/market-data/get-part-orderbook),
[KuCoin: правила пары](https://www.kucoin.com/docs-new/rest/spot-trading/market-data/get-symbol).

Проверка накопленных данных и гипотез: `/shorts research`, `/paper research [fast|base|stress]`.
Методика и ограничения — [docs/STRATEGY_RESEARCH.md](docs/STRATEGY_RESEARCH.md).
