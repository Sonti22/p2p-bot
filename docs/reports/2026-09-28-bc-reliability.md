# Отчёт: cloud/bc-reliability (2026-09-28)

Ветка `cloud/bc-reliability` от `origin/main` 7d931e5, один коммит. Пункт ROADMAP «Метка надёжности сигнала,
часть 3 (BestChange-факторы)» остаётся `[~]`, в нём дописан итог.

## Что сделано
- **`p2p._bc_risks`** вызывается из `_risks` для каждой стороны связки. У бирж не делает ничего, у обменника
  (`ex == "BestChange"`) даёт две причины:
  - «<сторона>: выгрузка BestChange N мин назад — курс и резерв могли уйти», если `snap.ts − fetched_ts` больше
    `BC_STALE_MIN` (10 мин). Выгрузка обычно обновляется раз в BC_REFRESH (120 с), так что старая означает, что
    скачать её не удаётся. Время неизвестно (0) — причины нет;
  - «<сторона>: резерв обменника впритык (X× объёма круга) — может кончиться до перевода», если сумма резервов
    обменников стороны меньше `BC_RESERVE_MARGIN` (1.5) × `cfg.amount / цена`. Резерв берётся по нику и сети из
    стакана снимка (`snap.groups`), потому что у стека связки `avail` — это только взятый объём. Тот же обменник в
    другой сети в счёт не идёт.
  - Вес каждой причины 1: они влияют на метку, индекс надёжности и `score` (сортировка, выбор прогона).
- **`scripts/bc_fields.py info.zip [--file bm_exch.dat]`** — для ПК владельца, без сети. По каждой колонке файла из
  архива: заполненность, число разных значений, частые значения. У колонок с 2–3 значениями печатаются обменники с
  редким значением — так видно, есть ли флаг ограничения («белый треугольник»).

## Не сделано и почему
- **Флаг «белого треугольника».** Выгрузку из облака скачать нельзя: `api.bestchange.ru` не в разрешённых хостах
  сетевой политики облака. Проверено 2026-09-28: 403 «Host not in allowlist». Дальше — на ПК: скачать `info.zip`
  (тот же адрес, что у бота) и запустить `python scripts/bc_fields.py info.zip`. Если признак найдётся — добавить
  его чтение в `_bc_parse` и причину в `_bc_risks`; если нет — закрыть пункт как недоступный по публичным данным.
  Второй путь — разрешить хост в сетевых настройках облачного окружения.
- **Возраст отдельной строки курса в `bm_rates.dat`** — формат этих полей неизвестен по той же причине. Используется
  возраст всей выгрузки.

## Тесты — `tests/test_bc_reliability.py`, 5 штук
- резерв впритык (1.1×) — причина есть, большой резерв — нет;
- резерв стека из двух обменников складывается, другая сеть того же обменника не считается;
- старая выгрузка — причина только у стороны-обменника, свежая или неизвестная — нет;
- веса снижают индекс (две причины → 8/10);
- `bc_fields`: колонки, редкое значение флага с именем обменника, код 2 без файла.

## Сомнения
- Пороги 10 мин и 1.5× выбраны без данных. Вынести их в `.env` можно отдельным шагом, если владелец захочет крутить.
- Больше причин у связок с обменником — чаще метка ⚠️/🪤 и ниже `score`. Это нужное направление, но может заметно
  сократить сигналы с BestChange, если выгрузка часто не обновляется (BC_REFRESH, VPN).
