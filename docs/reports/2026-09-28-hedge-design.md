# Отчёт: cloud/hedge-design (2026-09-28)

Ветка `cloud/hedge-design` от `origin/main` 7d931e5, один коммит, только `docs/hedge-design.md`.

## Что сделано
Документ о том, как подключить хедж P2P-кругов шортом перпа к боту через ядро `trading/`. Прочитано: ветка
`cloud/trading-core` (HEAD `bcd39f1`: switch, gates, risk, journal, ownership, keys, venues), `simperp.py`, итоги
бэктеста хеджа в ROADMAP. Код ядра и тесты не менялись.

Разделы документа:
1. **Что хеджируем.** Только круги с BTC/ETH/TON на время удержания монеты. Что уже есть в main и в ядре: пороги `gates` для
   hedge, лимиты `risk`, `journal.submit`.
2. **Режимы.** paper / minlot / confirm / auto = минимум из режима в `.env` и режима, разрешённого порогами. Бумага
   остаётся в `simperp`.
3. **Когда открывать.** Только после фактической покупки монеты. Стоимость ≤ 0.6 запаса на курс, свежий ключ, нет
   «неизвестных» ордеров и чужих позиций, дневной стоп не исчерпан.
4. **Размер.** `hedge_ref_qty` = монета круга, округление вниз до лота. Одна группа ядра на круг. В minlot — ≤ 50 USDT.
5. **Площадка.** Стоимость по `simperp.choose` плюс фильтры живого режима. Стоп на бирже ставится только на Bybit.
6. **Вызовы.** Последовательность `check_open` → `submit`. Таблица закрытия по событиям круга: исполнен, сорвался
   на покупке, сорвался на переводе или продаже, таймаут, ликвидация.
7. **Кнопки.** Одноразовые, с nonce, живут 60 с, только владельцу. Команда `/hedge`, «⛔ Стоп торговли», понижение
   режима.
8. **Отказы ядра.** Реакция на каждый: Verdict, refused, rejected, unknown, события outbox, ошибки сверки, дневной
   стоп. Правило: при сомнении не открывать, закрывать своё можно всегда.
9. **Данные.** Какие поля писать для порогов `gates`: бумага — из `paper.db`, живое — из новой таблицы хеджей.
10. **Порядок внедрения.** Какие шаги может делать облако (статистика, запись плана без ордеров), а какие только
    владелец (кнопки и вызовы ядра).
11. **Открытые вопросы.** Момент продажи реального круга, смысл minlot для хеджа, лот ETH, тип маржи, пополнение
    маржи только вручную.

## Сомнения
- В ядре нет кнопок, круга и расчёта статистики — документ предлагает делать это в боте. Нужно решение владельца:
  где хранить хеджи (предложено — рядом с журналом сделок) и как бот узнаёт о продаже монеты в реальном круге.
- Порог «стоимость ≤ 0.6 запаса» взят из `gates` (`cost_to_buffer`). По бэктесту BTC проходит только при комиссиях ×1.
