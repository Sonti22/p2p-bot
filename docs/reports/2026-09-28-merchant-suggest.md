# Отчёт: cloud/merchant-suggest (2026-09-28)

Ветка `cloud/merchant-suggest` от `origin/main` 7d931e5, один коммит.

## Что сделано
- `scripts/merchant_suggest.py <snapshots.db> [--days N] [--min-merchants 5]` печатает пояснение по каждой площадке и
  последней строкой — `MERCHANT_MIN=HTX:300/96,MEXC:100/95,…`. Коды выхода: 0 — есть предложение, 1 — данных нет
  ни по одной площадке, 2 — нет файла.
- **Метод** тот же, что записан у `MERCHANT_MIN_SUGGESTED` в p2p.py:
  - берутся уникальные мерчанты площадки по всем монетам и обеим сторонам, у каждого — последние увиденные сделки и %;
  - сделок — 25-й перцентиль (линейная интерполяция), вниз до одной значащей цифры;
  - % — 10-й перцентиль без выбросов ниже 90%, вниз до целого;
  - итог не мягче 100/95: `max(сделок, 100)`, `max(%, 95)`;
  - BestChange пропускается (у обменников отзывы, а не сделки);
  - площадка с числом мерчантов меньше `--min-merchants` — «мало данных», в строку не попадает, у неё остаётся общий порог.
- **Чтение базы**: только на чтение (`file:…?mode=ro`), файл не создаётся и не меняется. Из строк `scans` берутся
  ссылки групп (пакет, номер) → площадка, каждый пакет разжимается один раз. Снимки версии 1 (без групп) пропускаются.
  Формат строк объявления берётся из `snapshots.AD_FIELDS`.
- В README, раздел «Запуск», — строка про скрипт.

## Сомнения
- У мерчанта берутся последние значения, а не максимум: счётчики сделок у Bybit «недавние» и могут падать.
- Перцентили считаются по мерчантам, а не по объявлениям, поэтому мерчант с десятком объявлений весит как один.
- `--days` считает от текущих часов, а не от последнего снимка: по старой копии базы нужен `--days 0` (по умолчанию все снимки).
