## Что сделано (без стратегий и без автоматических ордеров)
Вся логика — в `trading/wiring.py` (внутри защищённого пакета); в `bot.py` — только явные хуки:
1. **Старт.** `bot.main`: `trading.switch.switch_from_file(ENV_PATH)` и `trading.gates.flags_from_file(ENV_PATH)`
   сразу после выключателя выплат (TRADING, TRADING_MODE, TRADING_SHORT_PAPER — только из файла .env; окружение не
   включит и не поднимет). Затем `wiring.startup`: `journal.resume`; если сохранён торговый ключ — `keys.startup_check`
   (права у самой биржи). Ключ с лишними правами (вывод, переводы…) — `switch.disable()`; `TRADING=1` без проверенного
   ключа — тоже. Режим маржи (`venues.margin_mode`: Bybit — аккаунт, BingX — по BTC-USDT) + `risk.startup_warnings` —
   одним сообщением владельцу. Без ключей и с TRADING≠1 — молча. Сбой старта — торговля выключена, бот работает.
2. **Цикл** `wiring.loop` — отдельной задачей (`bot.trading_task`, как perp_loop; строка `asyncio.gather` с
   payouts_loop не тронута): раз в 30 с `journal.reconcile` (если есть проверенные ключи), дневной стоп — событием
   `day_stop` (раз в день МСК), `trading_state.json` для launcher, доставка outbox: русский текст на каждое событие
   ядра (unknown, mismatch, notfound, rejected, resolved, closed_by_venue, settled, overfill, spot_dust, foreign,
   stop_missing, stop_removed, stop_breached, reconcile_error, watch_error, day_stop; незнакомое — «событие ядра …»),
   `mark_delivered` — только после `ok` Telegram, первая неудача — стоп до следующего цикла. Сбой ядра: лог, одна
   тревога владельцу (до первой удачной сверки), пауза 5 мин. Торговлей не пользовались (нет ключей и базы) — цикл
   базу не создаёт.
3. **/trading** — режим и причина запрета, ключи (keys.check_status), позиции бота со стопами («⚠️ без стопа»),
   результат дня против лимита, блокировки (unknown, неподтверждённые закрытия биржей, давняя сверка, дневной стоп),
   предупреждения старта, пороги gates по стратегиям (`journal._gate_mode`), ждущие подтверждения. Кнопки: «⛔ Стоп
   торговли», «⬇️ <режим>» (только ниже текущего), «🔄 Обновить».
4. **Подтверждение ордера**: `wiring.request_order(bot, order, strategy, group)` → карточка с точным ордером и
   кнопками `trd_ok:<token>` / `trd_no:<token>`. Токен — `secrets.token_urlsafe`, одноразовый (забирается при первом
   нажатии), живёт 120 с, привязан к намерению (ордер, стратегия, группа) и к message_id карточки. По «✅» —
   проверка `switch.can_open()` в момент нажатия и ещё раз перед отправкой, `journal.submit(purpose="open", mode=…)`
   фоновой задачей, итог — владельцу. Карточка не создаётся при TRADING=0, paper, без проверенного ключа, для
   уменьшающего ордера. `request_order` в боте никто не вызывает (стратегий нет); единственный вызов
   `journal.submit` в подключении — за подтверждённым токеном (тест по AST).
5. **«⛔ Стоп торговли»** — `switch.stop_and_persist(save_env)` (TRADING=0, TRADING_MODE=paper в .env и в процессе),
   все висящие токены погашены. Режим — только `switch.lower_and_persist` (повысить нельзя).
6. `.env.example` — TRADING=0, TRADING_MODE=paper, TRADING_SHORT_PAPER=0 и понижающие лимиты TRADING_MAX_*/
   TRADING_DAILY_LOSS_USDT/TRADING_MINLOT_* (пустое значение — потолок кода). `docs/owner-guide.md` — раздел
   «Торговля — /trading». `trading/__init__.py` — описание модуля wiring.

Доступ: `/trading` и `trd_*` обрабатываются только после `_owner_gate` (владелец в личном чате): группа —
«refuse», гость — GUEST_DENIED/запинённый on_guest_callback (trd_* ему не пропускает), чужой — игнор. `/trading` в
dispatch дополнительно не срабатывает в контексте гостя. Запинённые функции выплат и гостей не менялись.

## Тесты — `tests/trading/test_trading_wiring.py` (21, через helpers.arun)
Старт без ключей (TRADING=1 → выключено + сообщение; TRADING=0 → тишина), ключ с правом вывода → выключено, все
предупреждения одним сообщением, выключатель только из файла; outbox помечается доставленным только после ok (502 —
остаётся), русские тексты и экранирование, дневной стоп раз в день; сбой ядра — цикл жив, одна тревога, пауза; сверка
только с ключами; /trading владельцу; /trading и trd_stop недоступны группе, гостю, чужому и чужому нажатию в чате
владельца; ордер только по подтверждённому токену; токен одноразовый, с TTL, привязан к карточке, «✖️» гасит; trd_ok
после TRADING=0 ничего не шлёт; стоп пишет TRADING=0/paper в .env и гасит токены; режим из Telegram не поднять;
journal.submit — только в `_submit`, в bot.py нет ни submit, ни request_order.
Мутационная проверка: 8 мутаций wiring.py (токен не гасится, доставка без ok, нет проверки выключателя при нажатии,
нет TTL, нет привязки к карточке, стоп не гасит токены, ключ с выводом не выключает, тревога каждый раз) — каждую
ловит хотя бы один тест.

## Сомнения / на ревью владельца
- BingX: режим маржи — по символу; при старте читаю только BTC-USDT (ядро перед открытием всё равно проверяет свой
  символ и ставит изолированную маржу).
- Сверка раз в 30 с при наличии ключей — 1–2 запроса на биржу за цикл на символ бота; на ПК стоит проверить лимиты.
- Лимит дня в /trading и `day_stop` — `risk.limits("hedge", режим)["daily_loss_usdt"]` (общий для стратегий);
  ограничение «не больше 2% капитала» ядро применяет при открытии, в /trading — только текстом.
