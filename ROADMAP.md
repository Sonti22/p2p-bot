# ROADMAP — очередь улучшений бота

Облачный Claude запускается 3 раза в день и берёт **первую невыполненную** задачу из «Очереди».
Протокол — в `CLAUDE.md`. Выполнено: `[x]` + дата + одна строка итога. Большую задачу дробить: сделать
первую часть, остаток — новой строкой сразу под ней.

## Очередь

### Учёт сделок и комиссий (приоритет)
- [x] Журнал сделок: кнопка «✅ Сделал» под сигналом → SQLite `data/trades.db` (время, связка, сумма, расчётный %); `/stats` — день/неделя/месяц. (2026-09-24 — `trades.py` (журнал) + кнопка `did:<id>` в `deal_markup`/`Bot.mark_done` и команда `/stats` в bot.py.)
- [ ] Лимиты СБП по банкам: учёт отправленного за календарный месяц из журнала сделок → предупреждение у 100 тыс. ₽, авто-`PAY_FEE` для банка сверх лимита.
- [ ] Своя сумма круга: в «⚙️ Настройки» кнопка «✏️ Своя сумма» → бот просит ввести сумму (1 000–5 000 000 ₽; понимать «20000», «20 000», «20к», «1,5 млн»), сохраняет `AMOUNT` и сразу делает внеочередной скан под эту сумму: присылает 📊 топ-график и 🔥 карточку лучшей связки. Плюс команда `/calc 20000` — разовый расчёт под сумму без смены настроек (скан с копией Config через `dataclasses.replace`; кэш `_alt` для другой суммы не переиспользовать — лимиты объявлений зависят от суммы). Тесты: разбор суммы, отказ на мусор/вне диапазона, фильтр лимитов объявлений под сумму.

### Надёжность 24/7
- [ ] `/status`: версия (git sha), аптайм, время и длительность последнего скана, ошибки по площадкам, сколько связок выше порога. Версию и последние коммиты брать из `.dev_status.json` (его пишет launcher.py) — без subprocess/git в коде бота (guard блокирует); см. `dev_view` в bot.py.
- [x] Алерты: площадка недоступна >15 мин или скан падает 3 раза подряд → сообщение в Telegram (не чаще раза в час на площадку), и сообщение о восстановлении. (2026-09-24 — `Bot.check_venues` в bot.py: стрик ошибок и таймер простоя по площадке, алерт с кулдауном, сообщение о восстановлении.)
- [ ] Логи в файл `logs/bot.log` с ротацией (logging + RotatingFileHandler, 5 × 1 МБ) вместо print; команда `/logs` — последние 30 строк.
- [ ] Backoff по площадкам: после ошибки площадка пропускается с растущей паузой (30 с → 10 мин), чтобы не ловить бан; сброс после успеха.

### Качество сигналов
- [ ] Спот HTX и KuCoin в `spot_prices`/`_route` (публичные тикеры), чтобы их связки не гонялись через спот Bybit.
- [ ] «Живость» связки: хранить, сколько сканов подряд связка в топе; в карточке «держится N мин»; сигнал только если держится ≥2 скана (настройка).
- [ ] Условия мерчанта: забирать remarks/terms (KuCoin `remarks`, MEXC `tradeTerms`, BitPapa `conditions`), отсеивать «третьи лица», «только верифицированные», «в чат»; ключевые условия — строкой в карточке.
- [ ] Скоринг риска 0–100 (отклонение от ориентира, сделки/отзывы, волатильная монета, число переводов); показывать в карточке, сортировать сигналы по «прибыль × надёжность».
- [ ] Комиссии вывода вынести из кода в `fees.json` (биржа → монета → сеть → комиссия, дата проверки); `/fees` показывает таблицу и возраст данных.

### Учёт и аналитика
- [ ] Ввод фактического результата сделки (кнопки/ответ числом) → `/stats` показывает расчёт vs факт.
- [ ] История спредов: раз в 5 мин лучший % по каждой паре площадок в SQLite; `/history` — картинка «лучшее время суток» за 7 дней.

### Удобство
- [ ] Фильтры монет и площадок кнопками в `⚙️ Настройки` (вкл/выкл, сохраняется в `.env`).
- [ ] Тихие часы (настройка, например 01:00–08:00 МСК) + утренний дайджест: топ-3 за ночь.
- [ ] Команда `/why <номер>`: разбор связки по шагам с суммами в рублях после каждого шага.

### Площадки
- [ ] BingX P2P — только если данные доступны публично, без ключей и без обхода защиты; иначе закрыть задачу с пометкой «недоступно».
